# D · The Set — how it looks and feels

**KILLED** (director, concept building steer 1, 2026-11-13). Kept as the record. Its parts went: show-changes clouds → the shared viewer; the decisions register → C and E; codes → `common-how-it-works.md`. The Go to field, issues and Δ marks were dropped.

Product designer (visual focus), concept turn 1, 2026-11-13. Read with `how-it-works.md` (systems) and `../common-how-it-looks-and-feels.md`. Frames: `frames.png` (phone 1–7, desktop landing), `frames-desktop.png` (desktop 1–7). All at 1:1.

## I propose killing D. Here's why, then the full look anyway so the director can judge.
1. **Its anchor is the format the owner retired twice today.** D is a drawing set: sheet numbers, sheet letters, a sheet index, revision clouds on sheets. Then the owner said "why make anything on a3 at all?" and "text should be html": new work arrives as markdown plus separate images, not sheets. From here on D's "sheet index" is a list of docs and images with codes. That's a plain table, and the drawing-set language only fits the legacy part of the project.
2. **Drawn at both sizes, it's the least visual and the emptiest.** The desktop landing (`frames-desktop.png` 1) is a title block, three revision rows and a ten-row table, with **half the screen empty grey**. The director's worry about C ("a spreadsheet") applies more strongly to D, and the director ruled D can't fix that with thumbnails (it would turn into E).
3. **What's unique in it moves cleanly into C or E:**
   - the **"Go to" code field** (the one input; it fits a register, and it's the best J13 answer we have);
   - **"Show changes" revision clouds** on image compare, drawn from a real diff (proved in frame 3: the joystick, the closed view, the effects text and the footer, from v1 → v1.1). It works for any two images of the same size, not just sheets;
   - the **Decisions register** (date · his words · caused codes) as a history view;
   - **issues by day**, not per publish (below).

If the director keeps D, the look below stands.

## Pushes on the systems doc (if D stays)
- **Issue numbers per publish → issues by day.** Sessions publish many times a day: "Issue 14" by lunch, "Issue 140" in a month. That's the site's internal counter, not his project's. One issue per day with publishes ("13 Nov"); the revision table's in-progress row reads "Today · in progress · FOLD-D rev C" and becomes "13 Nov" at day end.
- **Δ without a number.** It means "changed since you looked" (signed-in). For a signed-out viewer it means "changed on the latest day", and the index header says so ("Δ = changed 13 Nov") so the mark never lies.

## Director's must-proves
1. **No-scroll landing with sections, not a 100-row wall:** phone frame 1. Title block (150 px), revisions (3 rows × 32), then **"Index by stage"**: 10 rows × 33 px (Concept 112 Δ3, Lock "v1.1 · 2 versions", Handoff … Assembly "not yet" in ink 2, Records 14 Δ1). It fits 714 px. A section opens its index.
2. **Feels live:** frame 2. The status cell goes ON (mid-dip), and a new top row slides into the revision table ("Today · now · in progress · FOLD-D rev C", 180 ms height + fade, oldest row drops). Concept's Δ ticks 3 → 4. It reads as live, just barely; the lamp does most of the work.
3. **Stays textual:** yes, until an item opens.
4. **Numbering holds across archive and next round:** the desktop index lists FOLD113-A, TYPECASE-A (rev A, dropped, greyed) next to current codes. Backfilled revs follow the common rule (HUSH-C stays rev A: footer-only change).

## Look
- **Title block:** a 1.2 px ink box. Name 21/600 and project line on top; a 1 px ink grid below holds Status (lamp + text) · Current set (v1.1 · 13 Nov) · Waiting on you (ONE SHEET or FOLD 14/600) · Go to (a white field with a rule border, placeholder "code, e.g. FOLD-A"). Labels are 10.5 caps. It's the only boxed element on the site, and it's boxed because a title block is.
- **Tables:** 1 px rule rows, 32–34 px tall. Codes 600, everything else 400. Rev letters, dates and status in ink 2. Current rows in ink, older in ink 2. Dropped rows at 40% with "dropped" in the status column. The now stage has a 3 px ink bar.
- **Δ:** a 1.2 px ink outline triangle, 7–10 px.
- **Revision clouds:** scalloped 1.1–1.4 px ink outlines around changed areas, bump radius 3 px on a phone and 6 px on desktop. Ink only; the scallop shape is the mark ("an unacceptable colour" from systems' draw, applied as shape). A toggle "Show changes from rev B" (44 × 20 ink switch) and "6 changed areas".
- **Test page:** a runs table (variant · peak · env. peak) whose rows are the A/B switch. The playing row has a 3 px ink bar and "playing". The sound block and the plot follow.
- **Desktop:** title block top right (520 wide), revisions top left (760), then the full index table (Δ · code · title · kind · rev · date · status · stage), one stage open at a time. An opened item replaces the index. Tablet: the same with title block and revisions stacked.
